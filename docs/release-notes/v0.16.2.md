## StockAI v0.16.2

> Google / Yahoo 访问不了的地区终于能抓到新闻了，同时一次分析的等待时间几乎砍半。

### 🐛 修复 / Bug Fixes

- **Google / Yahoo 不可达的地区，新闻抓取此前 100% 失败**：四条抓取策略全部解析到 `google.com` / `news.google.com` / `finance.yahoo.com`，这两个域名不通就一条新闻也抓不到。更糟的是失败会被报成「没有找到这只股票的相关新闻，请确认代码是否正确」——把网络不可达伪装成用户输错了代码，于是你会反复检查一个完全正确的股票代码。现补上**东方财富资讯**，它是唯一不依赖这两个域名的新闻源。实测在 Google 与 Yahoo 全部封禁的环境下，600519 与 AAPL 都能稳定拿到 8 条新闻。
- **一个不可达的域名就能吃光整份抓取预算**：Google News RSS 走的是没有超时的裸请求，被墙时会一直挂到操作系统 TCP 超时，60 秒的抓取预算全耗在它身上，后面的备用源一次都轮不到。**只加备用源修不好这个 bug**，两处必须一起改。
- **无效股票代码不再返回一堆不相干的新闻**：东财资讯是全文检索，搜 `600519` 会命中正文里出现过这串数字的无关文章。现按股票名与代码做相关性过滤，输错代码时仍然明确告诉你「没搜到」，而不是给你一批看似有用的噪音。

### ⚡ 性能 / Performance

一次 A 股深度分析实测 **21.9 秒**——这是全应用感知最强的等待（切换标的时自动触发），此前从未被测量过。三处已修：

- **股票信息不再被取两次**：拼新闻搜索词时拉一次公司名，紧接着又并发拉同一个接口一次。该数据源实测抖动 0.26–8.00 秒，多出的那次最坏白等 8 秒，还串在整条链最前面把新闻抓取一起顶后。
- **新闻正文提取改并行**：3 篇各约 4.3 秒、合计 12.85 秒，占整次抓取的 **59%**，而这三次几乎全是在等网络。A/B 对照证明提速**没有靠少抓内容换来**：同样 3 个链接，串行与并行提取出的正文逐条一致。
- **不再为一个搜索词干等**：公司名只是把 `601012` 变成 `隆基绿能601012` 的搜索优化，却挡在新闻抓取前面。现最多等 3 秒，超时就直接用代码去搜（实测用裸代码同样能拿到 8/8 条相关新闻）。

**合计**：美股 **10.3 秒 → 6.0–6.2 秒**；A 股在信息源打满超时的最坏情况下 **21.9 秒 → 10.2 秒**。剩余耗时几乎全是等新闻网站首屏打开，代码侧能做的已经做完。

## StockAI v0.16.2

> News fetching finally works where Google and Yahoo are unreachable — and a single analysis now takes roughly half as long.

### 🐛 Bug Fixes

- **News fetching failed 100% of the time where Google / Yahoo are blocked**: all four scraping strategies resolved to `google.com`, `news.google.com`, or `finance.yahoo.com`. If those hosts are unreachable, not a single article came back. Worse, the failure surfaced as "no news found for this stock — please check the ticker", disguising an unreachable network as a typo, so you would recheck a perfectly valid ticker over and over. This release adds **Eastmoney News**, the only source that depends on neither domain. Verified with Google and Yahoo fully blocked: both 600519 and AAPL return 8 articles reliably.
- **One unreachable host could consume the entire scrape budget**: the Google News RSS path used a bare request with no timeout, so a blocked host hung until the OS TCP timeout — burning the full 60-second budget and leaving no time for any fallback source to run. **Adding a backup source alone would not have fixed the bug**; both changes were required.
- **Invalid tickers no longer return a pile of unrelated news**: Eastmoney search matches full article text, so `600519` would hit articles that merely contain those digits. Results are now filtered by company name and ticker, so a typo still tells you plainly that nothing was found instead of handing you plausible-looking noise.

### ⚡ Performance

A deep analysis of an A-share stock measured **21.9 seconds** — the most noticeable wait in the whole app (it fires automatically when you switch tickers), and it had never been measured before. Three fixes:

- **Stock info is no longer fetched twice**: once to build the news search query, then again concurrently from the same endpoint. That source measured 0.26–8.00 s of jitter, so the redundant call cost up to 8 wasted seconds — and it sat at the very front of the chain, delaying news fetching behind it.
- **Article extraction now runs in parallel**: 3 articles at ~4.3 s each, 12.85 s total — **59%** of the whole scrape, and nearly all of it waiting on the network. An A/B comparison proves the speedup did **not** come from extracting less: for the same 3 links, serial and parallel produced identical content, article for article.
- **No more waiting on a search-term optimization**: the company name only turns `601012` into `隆基绿能601012` for search purposes, yet it blocked news fetching. It now waits at most 3 seconds and falls back to the bare ticker (measured: the bare ticker still returns 8/8 relevant articles).

**Total**: US stocks **10.3 s → 6.0–6.2 s**; A-shares in the worst case (info source timing out) **21.9 s → 10.2 s**. What remains is almost entirely news sites loading their own pages — there is nothing left to win on our side.

### 📦 Installation

**macOS** (current build matrix ships Apple Silicon only — no Intel x64 dmg)
1. Download `StockAI_0.16.2_aarch64.dmg` (Apple Silicon)
2. Open the DMG and drag StockAI into Applications
3. If macOS says "cannot verify developer": System Settings → Privacy & Security → Open Anyway

**Windows**
1. Download `StockAI_0.16.2_x64-setup.exe` and run the installer

**Linux**
1. Download `StockAI_0.16.2_amd64.deb`
2. `sudo dpkg -i StockAI_0.16.2_amd64.deb`

**First-time setup**
Open the app → Settings (top-right) → enter your AI provider API Key (OpenAI / DeepSeek / GLM / Anthropic / Ollama) → Save. Done.

> Users on v0.15.0 or later will be prompted to update inside the app — no manual download needed.
